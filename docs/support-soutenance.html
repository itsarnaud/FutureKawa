FutureKawa

Traçabilité et supervision IoT du café vert, du sac de l'exploitation à l'entrepôt d'exportation — sur trois pays producteurs, consolidée au siège.

Soutenance finale — Brésil · Équateur · Colombie

Le problème

Quatre angles morts dans la chaîne logistique

Conditions de stockage

Température et humidité suivies à la main, sans centralisation entre les trois pays.

FIFO non fiabilisé

Rien ne garantit que les lots les plus anciens partent en premier vers les torréfacteurs.

Traçabilité clients

Aucune preuve exploitable de l'historique des conditions à fournir aux acheteurs B2B.

Alertes manuelles

Dépassements de seuil et péremption détectés au constat, jamais en amont.

Architecture

Un backend par pays, un siège qui consolide

Le gateway interroge les trois country-api en parallèle, tolère la panne d'un pays, et n'applique aucune règle métier — il consomme des résultats déjà calculés côté pays.

Stack technique

Choix justifiés, pas par défaut

NestJS + Prisma

Architecture modulaire par domaine (lots, entrepôts, alertes), migrations et client typé.

Postgres × 4

Une base par pays + une base siège dédiée aux comptes utilisateurs — aucun partage de données entre pays.

Mosquitto (MQTT)

Un broker par pays, topic {pays}/{entrepot}/mesures, payload JSON minimal.

Next.js + Recharts

Tableau de bord siège : sélection pays, lots triés FIFO, courbes température/humidité.

Docker Compose

17 services orchestrés — 3 pays complets + siège + frontend + mail, démarrage en une commande.

GitHub Actions + Jenkins

CI automatique sur chaque PR/fusion (lint → tests → build → intégration → packaging Docker) ; pipeline Jenkins équivalent tenu en parallèle.

Sécurité

L'essentiel en place, le reste prêt à activer

Authentification JWT

Inscription/connexion sur le siège, mot de passe haché (bcrypt), jeton porteur de 2h, toutes les routes métier protégées.

Clé API interne & rate limiting

Implémentés (apps/country-api/.../common) mais désactivés pour l'instant : pas de déploiement en cours, priorité au confort de test.

CORS ouvert (dev)

Origine non restreinte pendant la phase de développement — le frontend et le gateway changent souvent de domaine (ports forwardés).

Documentation OpenAPI

Swagger généré et exposé sur /api/docs, gateway et country-api.

Démonstration

Ce que l'on va montrer en direct

  • Connexion, puis liste des lots triée FIFO avec statut visible (conforme / alerte / périmé)
  • Détail d'un lot : courbes température/humidité depuis sa date de stockage
  • Publication d'une mesure hors seuil via le simulateur IoT → alerte visible en quelques secondes
  • Traitement de l'alerte (acquittement) et vérification de l'e-mail dans Mailpit
  • Vue consolidée /dashboard/stocks : stocks par pays et par entrepôt

Qualité

Testé à plusieurs niveaux, pas juste au clic

Unitaire — Jest

23 tests : FIFO, calcul de seuils, péremption, ingestion MQTT — Prisma simulé.

Intégration — Supertest

7 tests contre un vrai serveur HTTP et un vrai Postgres : garde de sécurité, création de lot, mesures.

End-to-end

Simulateur MQTT (simulate-sensors.js) rejouant la chaîne capteur → alerte → e-mail sans matériel.

UI

Composants (Testing Library) et parcours navigateur (Playwright) sur le tableau de bord.
